# AES S-box `.unrail` collection

This directory contains the AES S-box circuits considered in the [CCHPC1.1 work](https://www.informatik.tu-darmstadt.de/impsec/publications_impsec/index.en.jsp), the AES S-box circuits listed in the [NIST Circuit Complexity AES repository](https://github.com/usnistgov/Circuits/blob/master/data/slp/aes/README.md) as of 2026-09-16, and the original 29-AND construction (35 files in total). Source-specific `.unrail` files are retained even where two entries represent the same circuit.

The recent 29-AND result reduced the known non-linear count for the forward AES S-box to 29. NIST subsequently published transformed forward and inverse circuits with different size/depth trade-offs. These are research/reference circuits; AES itself remains specified by [FIPS 197](https://csrc.nist.gov/pubs/fips/197/final).

> **Note:** NIST has since reorganized its repository (the historical SLPs moved to `old-2020/`, the current circuits are additionally listed under `aes-sbox/` and `aes-invsbox/`, partly with updated names) and added further circuits, including 28-AND forward and inverse S-boxes contributed on 2026-09-24. These newer circuits are not part of this collection yet; the file names below follow the listing of 2026-09-16.

## S-box filename naming

| Pattern | Meaning |
| ------- | ------- |
| `cchpc1_1_<name>.unrail` | Benchmark S-boxes in the CCHPC1.1 paper |
| `nist-aes-sbox-<dir>-g<g>-a<a>-d<d>-ad<ad>.unrail` | Historical NIST SLP |
| `aes-sbox-<dir>-a<a>-ad<ad>-g<g>-gd<gd>-xx<xx>-<id>.unrail` | Current NIST-style circuit, checked 2026-09-16 |
| `aes-sbox-fwd-g224-a29-d34-ad6.unrail` | Original 29-AND circuit [[Umi26]](https://umizame.github.io/S-box_29-AND/) |

| Token | Meaning |
| ------- | ------- |
| `<dir>` | `fwd` = forward AES S-box, `inv` = inverse AES S-box |
| `<g>` | gate count |
| `<gd>` | gate depth |
| `<a>` | AND count |
| `<ad>` | AND depth |
| `<d>` | gate depth in historical NIST names |
| `<xx>` | XOR/XNOR count |
| `<id>` | NIST circuit identifier |

The names keep the metrics of the source listing. Three NIST circuits (`aes-sbox-fwd-a30-ad4-g205-gd15-xx175-54`, `aes-sbox-inv-a29-ad5-g186-gd16-xx157-43`, `aes-sbox-inv-a36-ad4-g148-gd14-xx112-24`) contain one NOT gate that is counted in `<g>` and `<xx>`. Unrail merges NOT gates into the neighbouring gadgets, so the tables below report one linear gate less for these circuits.

## Interface and bit ordering

All files use the same external interface and can be exchanged directly. `x0`/`s0` is the AES-byte **MSB** and `x7`/`s7` the **LSB**, matching the BP10/BP12 convention used in the CCHPC1.1 repository. All files were exhaustively checked over all 256 byte values after normalization.

## Statistics and ordering

All values are taken from the unrail results generated with `regenerate_results.sh`, which runs unrail in four configurations per S-box:

| Configuration | unrail flags | Description |
| ------------- | ------------ | ----------- |
| Normal, unoptimized | `--disable-f2b --disable-b2f` | Every gadget is dual-rail, no input registers |
| Normal, F2B+B2F | *(none, default)* | Front-to-back (F2B) and back-to-front (B2F) optimization enabled |
| Duality, unoptimized | `--duality --disable-f2b --disable-b2f` | As *Normal, unoptimized*, with duality gadgets |
| Duality, F2B+B2F | `--duality` | As *Normal, F2B+B2F*, with duality gadgets |

NOT gates are merged into the neighbouring gadgets in all four configurations.

- **Structure** columns follow Table 4 of the CCHPC1.1 work. The two **total** columns are the gadget counts of the unoptimized circuit, in which every gadget is dual-rail. The remaining #Non-linear and #Linear columns split these totals according to the **F2B+B2F** result (`--duality` yields exactly the same split): `DR` counts the gadgets that stay dual-rail, `DR2SR_B2F` the non-linear gadgets that B2F turns into dual-rail-to-single-rail gadgets, and `SR_F2B`/`SR_B2F` the linear gadgets that F2B/B2F turn into single-rail gadgets. `#REG` counts the single-rail-to-dual-rail input registers inserted by F2B+B2F (the unoptimized modules have none). `Depth (NL), unoptimized` is the gadget depth of the unoptimized circuit with the non-linear (AND) depth in parentheses, and `Depth, F2B+B2F` the gadget depth of the generated module after F2B+B2F as reported in the unrail statistics.
- **Area** columns are the synthesized area in GE of the module generated in each of the four configurations, for security orders `d = 1, 2, 3`. The modules were synthesized with `synthesis/synth.tcl` (Yosys, NanGate 45 nm Open Cell Library, CCHPC1.1 gadgets built from the `dont_touch` cells in `synthesis/basic_components.v`), 1 GE = 0.798 µm² (NAND2_X1). The area includes all gadgets and registers, but not the generation of fresh randomness.

Rows are ordered by the **ranking score**, which uses the **Normal, F2B+B2F** configuration only: the synthesized **first-order (`d = 1`) area after F2B+B2F plus fresh-randomness generation**. The unoptimized area does not enter the ranking. The CCHPC1.1 work uses **39.4 GE per fresh random bit**. Every CCHPC1.1 non-linear gadget (DR-to-DR as well as DR-to-SR) consumes `d(d+1)/2` fresh bits at security order `d`, i.e. 1 bit at `d = 1`, so the score is the *Normal, F2B+B2F* `d = 1` area plus `39.4 GE × #Non-linear`. Duality does not need additional fresh randomness (the two duality copies of the dual-rail randomness carry the same bit in alternating pre-charge phases), so the **duality rank** applies the same randomness term to the *Duality, F2B+B2F* `d = 1` area. Equal scores are ordered by the unoptimized total depth and then non-linear depth.

This makes the ranking substantially more favorable to low-NL circuits, but it is **not strictly identical to sorting by #Non-linear**: sufficiently large differences in linear logic can still outweigh one or more fresh-random bits.

Across all S-boxes, F2B+B2F reduces the synthesized area compared to the unoptimized module by 8.3–20.8 % in normal mode and 10.0–23.4 % with duality at `d = 1` (10.8–23.9 % and 12.2–26.6 % at `d = 3`). With F2B+B2F enabled, duality costs 1.69–1.79× the normal area at `d = 1` and 1.73–1.78× at `d = 3`.

## Inverse AES S-boxes

These compute `InvSubBytes` and are ranked separately using the same first-order area-plus-randomness model.

## Validation and reproducibility

Every `.unrail` file was checked for the common interface and required I/O annotations and exhaustively evaluated over all **256** byte inputs against the forward or inverse AES S-box.
The generated modules of all 35 files (with and without F2B+B2F, normal and duality) were simulated with the share-accurate testbenches in `/testbench`, and the gadget counts and critical depths in the unrail statistics were cross-checked against the generated netlists.

All results (unrail outputs, statistics, area reports and synthesized netlists for `d = 1, 2, 3`) can be reproduced with `regenerate_results.sh` from the repository root.
